# PrivateVault：平台验证收尾与后续设计边界

版本：v0.1 · 日期：2026-10-28（Asia/Shanghai）

状态：**按用户最新决定，当前基础平台验证阶段先收尾，Windows 实机验证暂缓，不阻塞后续需求与架构设计。** Windows 仍是目标平台，状态为“基于共同核心的可行性预期，未实机验收”，不改记为已通过。Mac、Android 已有结果按原证据保存，不再追加终端实测或自动开始产品开发。

用户原话：“windows 可以先放一边，目前没有设备在身边，但安卓端已经跑通了，windows 端应该也行，验证可以先放下。”

本文补充当前推进顺序，保留[需求与架构 v0.2](../../PrivateVault-需求与架构设计-v0.2.md)和 v0.1 的历史。v0.2 中将三端可行性列为 P0 的原文不删除；当前明确延后 Windows 的实机门槛，不取消 Windows 产品目标，也不授权安装、部署或业务代码实现。

## 1. 本阶段已得到的依据

| 能力 | 当前依据 | 结论边界 |
|---|---|---|
| Mac 普通/Crypt 上传与解密读回 | 隔离实例实际请求，样本长度/摘要核对 | 已通过既定自制样本；不代表全库或任意编码 |
| Mac 视频正常范围读取 | 12 项正常范围字节一致，8 项核心冷启动并记录上游增量 | 当前样本支持范围读取；严格 14 项中的普通越界响应仍有一项差异 |
| Android 图片及加密音视频 | 用户实际操作并反馈图片、音视频及约 22/40 秒定位正常 | 读取、解密及可见播放/定位通过；没有手机上游字节/严格 Range 协议测量 |
| Android 加密上传 → Mac 解密读回 | 用户上传 PNG 后，Mac 实际完整读回 9,763 字节，SHA-256 与源图一致 | 当前 PNG 跨端完整性通过 |
| Windows | 同类桌面核心与协议有源码基础；本轮没有设备 | 暂缓实测，合理预期，不记为运行成功 |

## 2. 当前接受的推进假设

1. 继续采用“设备本地 OpenList/Crypt＋百度存储”的底层方向。已配置设备直接访问云端并本地解密，Mac 不必作为手机媒体服务器。
2. Windows 预计可以复用核心文件访问与 Crypt 接口，先按统一接口保留其适配位置；打包、进程管理、文件权限和播放表现待有设备时验收。
3. 现成 OpenList App 的配置导入可用于底层验证，不等于 PrivateVault 独立账号、自动配置恢复或元信息同步已经实现。
4. 当前证据足以继续设计整合层，不要求先完成所有后台、离线、大文件和 Windows 测试才讨论架构。上述未知项保留为后续验收及风险，不能在交付说明中宣称已覆盖。

Windows 实机缺失只是当前验证顺序调整，不隐式确定最终各端的发布顺序，也不取消三端均可本地上传、加解密和播放的已确认目标。

## 3. 下一步设计应收敛的内容

| 设计项 | 下一份具体方案应回答 |
|---|---|
| 客户端与本地核心 | PrivateVault 怎样承载/管理核心、提供统一界面和文件选择；桌面与 Android 共享哪些接口、各自承担哪些原生适配 |
| 账号、凭证与密钥 | 可信配置服务与本地执行如何分工；库配置如何完整恢复、版本对账；有效配置下的媒体访问如何避免依赖 Mac 在线 |
| 媒体资料与同步 | 库内专用资料区、每端本地索引、提交记录与冲突处理；不把 SQLite 文件直接同步或把手动导入称为自动同步 |
| 下载/归档任务 | 来源解析、下载、探测、上传、完整性验证、资料提交的职责和状态；失败、重试、空间预算与清理怎么衔接 |
| 首版边界与任务拆分 | 先形成可审阅的纵向闭环、输入输出和接受条件；将首次实现范围与后续离线、订阅、其他平台验收分开 |

宿主、语言和依赖按实际集成、维护及分发成本比较。现成 App 能运行不等于它已经提供稳定的跨 App 控制 SDK，也不直接决定 PrivateVault 必须沿用整套包装层。

这些属于后续方案收敛工作，当前没有把未讨论的具体技术栈或实现细节写成用户已批准决策。

## 4. 保留的风险，不作为本轮新增测试指令

- Windows 暂缓实测；实际宣称 Windows 版本可用前，应补做安装/运行、文件选择、上传、播放及生命周期验收。
- Android 后台/锁屏、主动离线、长音频和大视频暂存没有由短样本证明，按后续功能阶段验证。
- Mac 普通越界 Range 返回 400 而非预期 416，错误正文可能含上游链接；整合层仍需统一协议错误与过滤敏感信息。
- 密码不一致曾表现为空列表。需要完整配置核对/小样本自检和可理解的错误提示，避免把解密失败解释为没有媒体。
- 凭证到期、轮换、多端状态版本和新设备恢复未充分验证，不能反复用旧备份覆盖最新状态。
- Pixiv 具有现成解析支持证据，但用户授权/真实下载与跨端运行尚未验收；hanime1 支持状态仍未证实，不静默替换来源或宣布完整双来源首版已可行。
- 上传完成不能仅依赖列表、HTTP 200 或进度；原半成品发现仍要求验证后提交和重启对账。

保留风险不等于当前必须继续开展相应实测。后续可以先只读研究和设计接口，实际安装、账号连接、云端写入、部署或业务实现仍按当次具体范围处理。
