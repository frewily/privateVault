版本：v0.1 · 日期：2026-10-26（Asia/Shanghai）

状态：**本机只读准备与第一方资料核对完成；阶段 A、B 均未执行。** 本轮没有安装、解压或运行 OpenList/rclone，没有启动本地服务、登录网盘、读取既有凭证或上传文件，没有编写 PrivateVault 实现代码。

本文件承接研究 00—03，给出可审阅的下一阶段范围。新增证据不代表运行验证通过，也不自动批准安装或执行。已有 v0.1/v0.2 设计稿和研究 01—03 保留原样；研究 00 仅增加本次进展入口。

## 1. 推荐先批准什么

**先做阶段 A：独立官方核心＋自制文件的本地验证。阶段 B：百度验证，待授权方案明确后再批准。**

原因：本机虽然已有可用百度挂载，但其授权方式尚不确定；现有 Desktop 的严格签名检查也未通过。把这套环境保持原样，使用独立核心和不含个人资料的样本，可以先验证本机核心、Crypt、读回与范围处理，而不复制既有一次性刷新令牌。

阶段 A 不证明百度 API、真实云端 Range、网站来源、Android/Windows 或统一账号实现可用。它只关闭最基础的本机执行与格式问题。

## 4. 百度第一方资料的新结论

研究 03 在当时未取得第一方文档。本次已经成功读取官方文档入口及创建应用、授权、配额、预上传、分片上传、下载等正文。网页更新日期不同，不能把所有段落都归为同一版接口规则。

### 4.1 刷新令牌不是可以无协调复制的长期配置

官方授权码、设备码及快速授权文档都说明：访问令牌通常为 30 天；刷新令牌单次使用，刷新后必须保存新的值，不能继续用旧值。授权码同样一次性并有短期有效窗口。[B1][B2][B3]

授权码文档还说明刷新失败可能使旧刷新令牌失效，并给出刷新令牌的长期有效期限说明。**长期期限不等于可重复使用**；网络失败和不确定的刷新结果也不能简单无限重放旧值。

影响：v0.2 的多端自动配置必须增加刷新所有权和版本协议。直接给每台 OpenList 复制同一份刷新令牌，让各端自行刷新，不能作为已确认方案。

**建议继续研究的优先方案**：可信账号服务作为同一授权链的唯一刷新者，序列化刷新并保存最新值；已配置设备用有效访问凭证直连存储。它保留本机媒体访问，但服务长期离线且访问凭证到期时，需要等待服务恢复或用户重新授权。

若需要凭证到期后也不依赖中心，需验证百度是否支持本项目所需的真正独立设备授权链，不能先假定“各端重新登录一次”就互不影响。以上是技术建议，不是已实现或用户已批准的凭证协议。

### 4.2 指定目录必须同时落在应用授权范围内

“权限与配额”说明目录权限属于具体用户与具体应用的授权关系；默认目录通常是 `/apps/{appname}`，额外目录取决于平台允许的目录授权。操作还要满足对应接口权限。[B4]

“创建应用”说明 2026-06-03 后新创建应用的若干文件接口受应用目录限制；“预上传”明确列出 `/apps/{appname}` 的路径边界。[B5][B6]

另一方面，“快速授权”提供用户选择目录及其子目录、保存 `authorized_paths` 的描述，并使用不同于旧授权说明的权限名称和令牌接口。[B3]

这些资料不能合并成“新建应用即可任意管理现有网盘目录”。目录级授权与具体旧/新接口、OpenList 驱动及应用资格的组合仍需核实。

影响：

- PrivateVault 中的用户选定目录，还必须属于该应用真实获得的目录权限。
- 新应用能够操作自己的应用目录，不证明能接入全部既有收藏目录。
- 现有 OpenList 挂载可用，不代表新建 PrivateVault 应用自动继承同样权限。
- 不通过旧链接、路径构造或缓存记录规避授权范围；目录选择界面应体现真实可用范围。

### 4.3 旧授权说明和目录级授权不能直接互换

旧授权码说明使用 `basic,netdisk` 及相应 token 端点；快速授权文档列出目录级权限、`authorized_paths` 和另一组接口说明。[B1][B3]

所查 OpenList 固定版本采用的百度刷新路径与配置格式，不能仅凭字段都叫 access_token/refresh_token，就认定兼容新目录级凭证。需要确认目标接口、响应结构和授权范围；本轮没有把新凭证塞进旧驱动测试。

### 4.4 下载有第一方请求头与范围说明

官方“下载”文档明确列出百度 User-Agent、下载地址鉴权参数、Range 和重定向说明；给出 dlink 8 小时有效期，并说明超过 50MB 的文件不能用浏览器直接下载，应由原生软件/App 下载。[B7]

这为“当前设备的本地服务获取云端内容，再向 UI/播放器提供读取”提供文档依据。OpenList 驱动给链接配置的一小时缓存，与官方说明的 dlink 有效期限不是同一概念。

仍须真实测明文/密文读取、请求头、签名、重定向、冷缓存拖动耗时及流量。文档支持 Range 不等于某账户/路径/代理组合已经通过。

### 4.5 配额与上传条件要按应用状态判断

官方配额页说明权限按应用划分；其未审核状态表格包含每小时 10 次的频率说明。创建应用页又区分个人使用与公开发布、审核和人数限制。[B4][B5]

不能把某一表格直接套成“所有个人应用都只有同样配额”或“已有 SVIP 就没有配额限制”。实际应用类型、批准状态、接口和返回码仍需核对。阶段 B 若遇限额应停止并记录，不做压力测试或无限重试。

官方分片文档要求通过接口取得上传域名，而非在产品中固定示例域名；预上传/分片路径与权限、分片 MD5、上传会话需要保持一致。[B6][B8]

旧版 OpenList 文档中“30 秒内必须传完分片”的说法已有删改和不同实测说明；本次不把旧数值或驱动客户端超时当作百度最新服务保证。[G2]

## 5. 阶段 A：本机样本验证的具体提案

### 5.1 范围与网络

批准后才执行：下载并校验上述官方核心，使用新的临时配置、数据、文件、密文、读回和日志目录；生成自制样本；启动独立核心；完成本地读写、Crypt 和范围验证；停止这个独立进程。

网络范围：官方 GitHub 发行包及必要的公开发行元信息读取，本机环回接口。不配置百度或来源站凭证，不触发云盘文件请求，不做 Pixiv/hanime1 归档。若核心启动出现额外未说明的网络或系统权限需求，先停止核查，不自动批准。

“本地验证”指文件处理不接入云盘；下载官方工具本身仍使用网络，不能称完全无外联。

### 5.2 隔离目录与监听

候选工作区：`/private/tmp/privatevault-validation-20261026-<唯一标识>/`，执行前确认不存在后新建，当前尚未创建。

子目录建议：`package/`、`core-data/`、`work/`、`fixtures/`、`cipher/`、`readback/`、`private/`、`logs/`。

- 不使用项目仓库存储凭证、真实云盘配置或临时密钥。
- 不读取、修改或复制现有 Desktop 的用户数据目录。
- 核心只监听 `127.0.0.1`；候选 HTTP 端口 15244，执行前重查，冲突则停止重新说明。
- 不注册开机启动/后台常驻，不修改系统代理或防火墙，不增加其他网络服务。
- 显式核对 HTTP/HTTPS/S3/FTP/SFTP/MCP 等配置。源码默认 HTTP 地址为 `0.0.0.0`，因此不能直接把默认启动当作只监听本机。[G3]
- TempDir、数据库和日志均指向该工作区，目录访问限制为当前用户。

### 5.3 样本与资源上限

仅生成自制技术样本，不扫描用户媒体：静态图 1 个、短 PCM 音频 1 个、通用编码 MP4 1 个。视频目标 32—64MiB，全部明文合计上限 100MiB；这是拟批准的首轮范围，不是正式产品大小上限。

可使用本机已有 FFmpeg 生成测试内容，不安装新媒体工具。若现有工具不能生成约定格式，停止说明，不自动安装替代依赖。

工作区预算建议 2GiB，系统可用空间保留至少 15GiB；执行中检查实际文件占用，超预算或不能可靠控制时停止。此处是操作预算，不声称已经建立内核磁盘配额。数据量不是性能基准，不能由此推断 6TB 库性能。

### 5.4 配置与秘密

仅配置指向测试目录的本地存储和新的测试 Crypt 视图。测试加密参数不能指向真实收藏库，也不复用用户现有密钥。

新 Crypt 视图显式开启文件名与目录加密，编码候选为 base32，并把实际使用值记录在私有测试恢复资料中；这是测试参数，不是正式库格式最终决策。不更改已有 Crypt 配置。

本机管理密码或测试密钥如需初始化，由用户本人私下完成或由受保护的临时工具内部管理，不在模型输出、普通日志或项目文档里出现。启动输出不直接回显可能含密码的内容；必要日志先保护再脱敏。若不能完成安全初始化，先暂停，不通过复制现有管理员配置解围。

允许生成临时验证配置、必要的样本/检查命令与结果记录；不编写 PrivateVault 的业务、客户端、账号、下载适配器或部署代码。

### 5.5 验证步骤与预期

| 编号 | 操作 | 判定 |
|---|---|---|
| A01 | 摘要、解包范围、架构和版本核对 | 与固定发行来源一致；有系统安全阻拦则停止，不移除保护或重新签名 |
| A02 | 显式配置环回地址后启动 | 仅约定本机监听，数据与日志落在新目录，无其他存储连接 |
| A03 | 本地普通样本上传/读取 | 文件长度与 SHA-256 一致；无云盘行为 |
| A04 | 新 Crypt 加密与读回 | 测试密文目录名称/内容符合配置，解密读回 SHA-256 一致 |
| A05 | 首、中、尾与跨加密块范围读取 | 明文字节与样本对应区间一致，范围/总长响应符合预期；非法范围正确失败 |
| A06 | 本地图片、音频、视频播放 | 记录实际播放器、格式和行为；不声称云端/Android 已通过 |
| A07 | 一次受控中断和原设备重试 | 只停止新测试进程；恢复后结果可解释，不误标成功；不承诺字节续传 |
| A08 | 结果和退出 | 记录时间、版本、哈希、占用、通过/失败/未执行；停止新进程，不影响原应用 |

不得把本机文件系统的快速 seek 写成百度高效 Range 已通过。本地 Crypt 测试也不是独立 rclone 格式互读或三端验收；这些另列后续用例。

### 5.6 结束与保留

阶段结束停止本次独立进程。报告和经过脱敏的结果可以加入项目；临时环境及受保护测试恢复资料先保留供审阅，保留/清理范围明确后只处理该唯一工作区。

不删除、移动现有应用和用户文件；阶段 A 不创建云端对象，所以没有云端清理动作。用户若中途撤销本阶段授权，停止任务并报告完成到了哪一步。

## 6. 阶段 B：百度验证的准入条件（本次不请求执行）

阶段 A 通过后，阶段 B 仍需独立确认：

1. 采用的应用身份、直接或在线刷新方式、凭证流向和实际允许目录；不复制既有刷新令牌到并行实例。
2. 是否在允许范围内新建专用测试目录，以及实际配额。默认不访问用户未指定的目录。
3. 秘密由用户私下授权/配置，模型不读取或回显；不自动申请应用、扩大权限或取消既有授权。
4. 本轮云端对象数量、上传/读回次数、总数据范围、重试限制和保留策略。遇到权限/配额错误停止。
5. 先小样本普通与加密上传/读回，再做冷缓存范围与实际云端入站流量观察。不能只看本地 HTTP 206。
6. 令牌刷新和多端配置另做方案/验证；不故意使现有真实刷新令牌失效来做故障注入。

已有挂载可用是有价值的用户反馈，不能替代本阶段的授权与隔离条件。若需要使用现有环境或排查其签名，应先另行说明具体范围，不并入阶段 A。
