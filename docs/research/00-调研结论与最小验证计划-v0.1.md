## 4. 需要吸收进后续设计的实际发现

- OpenList Mobile 的部分管理密码设置代码会记录密码；复用包装层需要处理敏感日志，不直接照搬。
- gallery-dl 的现成 Pixiv 授权存在浏览器交互及敏感输出/缓存，不是已经集成好的移动登录 SDK。
- 本次 yt-dlp 要求 Python ≥3.11；候选嵌入 SDK 的默认 Python 版本未必满足要求，必须显式核对。
- 下载工具历史只代表本地下载记录，不能代替网盘归档成功记录。
- Crypt→百度上传存在完整密文暂存分支；工作区配额需要覆盖真实峰值。
- 百度上传进度 helper 是内存缓存；首版按阶段恢复/重试，不承诺任意重启后字节续传。
- 本地 206 可能建立在上游从头读取的兼容回退上；快进必须结合冷缓存耗时和流量验证。
- 新加密库必须明确名称和目录加密参数；输入密码并不自动等于完整保护所有文件名。
- 本机 OpenList 刷新后的凭证与中心配置需要版本对账，避免旧配置覆盖新令牌。
- B2 当前样本的正常云端范围通过；普通越界仍返回 400，且错误页含上游 URL/查询参数。媒体适配层需要统一 416 和敏感错误过滤，不能把正常播放通过视为所有协议及安全细节已解决。
- Android 测试入口密码不一致曾表现为空列表，单项修正后 PNG 解密显示恢复。后续需库配置核对/小样本自检和明确参数错误提示，不直接把空列表解释为没有资料。手机本地核心直连百度时，Mac 不在媒体数据路径中，避免重复以 Mac 休眠作为每种媒体的必过门槛。

这些是研究发现和技术建议。现有 v0.1/v0.2 设计文档未被自动改写；后续阶段 A 的实际结果和半成品发现见上方链接。

### B. 首轮 Mac 基础样本验证（原草案，当前结果见报告 05、11、13）

候选样本范围：用户自有或授权的图片、音频、视频各 1 个，总明文大小建议不超过 100MiB。该数值是便于控制首轮测试的草案上限，尚未获用户确认；不用于 6TB 容量或性能结论。

候选环境：独立的本机数据/工作目录和用户明确指定的新云端测试目录，避开既有收藏目录。实际空间配额在核查工具暂存策略后确定。

依次验证：

1. 合法授权、普通库上传、列举与完整读回校验。
2. 固定 Crypt profile 的加密上传；确认云端媒体与名称保护符合配置。
3. 解密读回比对原样本；检查临时明文、密文与缓存的实际路径和峰值。
4. 普通/加密视频分别测冷缓存首中尾范围与拖动，不仅查看 206。
5. 在受控样本上中断并由原设备恢复或重试；正确区分上传、验证和资料提交状态。

先使用本地自有样本验证百度链路，避免把网站解析和云盘问题混在同一个测试里。测试对象的保留/清理范围另外明确，不默认删除用户原件或既有云端资料。

### C. Windows / Android 独立性（历史草案；Windows 当前暂缓）

2026-10-28 当前决定以报告 19 为准：Android 已有上述基础证据，Windows 等设备可用时补验，不作为继续设计的阻断项。以下保留原测试草案，不代表当前要启动整组验证。

在各设备实际运行本地核心，记录驱动、配置与包版本；Mac 真实休眠/账号服务停止后，测试既有授权下的本机上传、解密读取与播放。

Android 另测文件选择、权限、空间不足、切应用、锁屏、系统终止和重新打开。外部播放器与本地解密服务要联合验收。没有在相应设备执行，就不能写成该平台已通过。

### D. 来源与统一账号整合（另行确认实现/验证范围）

在允许的授权途径明确后验证 Pixiv 单静态作品、多图作品、基础资料、下载与归档状态。hanime1 来源门槛独立保留，不由通用视频引擎或本地视频样本的成功替代。

账号自动恢复、服务器持钥、凭证版本、元信息同步和新设备接入需要相应实现或原型；本次研究没有授权提前编写这些代码。基础验证时的临时人工配置只用于证明底层，不代表改变最终统一账号体验目标。

## 6. 停止与重新评估条件

- 没有确认允许的授权途径，不进行真实账号连接。
