# BoxPlayer 借鉴与订阅归档决策

版本：v0.1 · 日期：2026-10-30

状态：本轮讨论的五项行为均由用户选择 A 确认。仅为设计记录，尚未实现或验证来源订阅；W01-A 研发仍待单独批准。

## 1. 路线与借鉴范围

用户决定继续原开发路线，将 BoxPlayer 作为参考仓库，不改用其自有加密格式、不整仓派生。已有 OpenList Crypt 资料作为兼容基线。来源分析见[源码调研 25](../research/25-BoxPlayer功能与核心需求源码对照-v0.1.md)。

跨语言主要借鉴业务不变量、接口边界、状态转移、恢复机制、错误交互与测试场景；TypeScript 实现仍可帮助理解调用顺序和失败处理，但不直接搬用 Electron 生命周期、影视模型或加密实现。

| 参考方向 | 与现有方案的关系 | 后续落点 |
|---|---|---|
| 提供者能力声明与证据等级 | 技术附录 20 已有能力抽象 | 存储接入时细化支持、未知与实测状态 |
| 任务持久化、抢占与租约 | 已有持久任务和恢复设计 | 任务模块内防止重复执行；本地租约不替代跨设备订阅分配协议 |
| 提交意图与落盘回读 | 已有 UploadAttempt 及校验后提交 | 处理请求超时和结果不确定，避免盲目重传 |
| 暂存、校验、入库分阶段 | 已有独立尝试路径与提交协议 | 保持完整解密回读 SHA-256 基线，不照搬仅检查落盘的标准 |
| 任务进度、失败原因和重试入口 | 需要在具体界面中细化 | 区分作品失败、共同依赖暂停、部分完成及等待手动处理 |
| 指定目录扫描、取消与限速 | 沿用指定目录范围 | 不扩大为全盘扫描；扫描增量不等于来源订阅增量 |

## 2. 已确认的五项行为

| ID | 用户确认 | 行为与完成条件 |
|---|---|---|
| B01 | 单件失败不阻塞其余作品 | 每件作品独立记录结果和重试，本轮可显示部分完成；授权失效、空间不足、目标库异常等共同依赖问题暂停受影响任务 |
| B02 | 默认跳过已归档作品 | 自动订阅只处理新增作品，提供手动重新归档入口；只有资产校验及资料提交均完成才算已归档，失败或未完成项不进入成功去重集合 |
| B03 | 来源移除不触发归档删除 | 取消收藏、作品删除或暂时不可见，均不自动删除已归档文件和元数据；用户主动移除及云端物理删除继续遵循既有设置和协议 |
| B04 | 多图作品全部成功才归档 | 本次作品归档计划内的全部图片均上传并校验成功后才提交作品；部分成功保留受控检查点，不发布为已完成作品，不阻塞其他作品 |
| B05 | 有限自动重试后等待手动处理 | 可重试的单件失败逐步延长间隔，达到预算后转失败并等待显式手动重试；后续普通订阅轮次不重置预算、不得无限复活该失败项 |

“后续每轮不重置预算”是本轮 B05 选项明确说明的行为，与 B02 的成功去重分别记录：未完成作品不会被误认为已归档，但耗尽预算后也不会自动无限尝试。

## 3. 实现时必须维持的边界

- 来源作品身份与文件摘要分别管理：作品级幂等不按标题或字节哈希简单替代；具体来源 ID/归档账本键在来源工作包冻结。
- 本轮不做已归档作品的自动版本追踪。手动重新归档如何呈现版本、替换或合并，保留到该功能设计，不默认覆盖已有资料。
- 复用已完成部分前核对来源、资源计划及文件完整性；来源变化、不可续传或上传状态不确定时，按附录 20 对账或新建 attempt，不能承诺所有平台字节级续传。
- 保留检查点不等于永久保留全部临时字节；工作区配额与活动引用仍适用。若副本已按明确规则清理，恢复时需重新获取，不能虚报可继续。
- 永久不可用、认证失效、限流、空间不足与暂时网络错误需要分类；不能把所有错误都消耗为同一种单件重试。限流遵循上游等待要求并作用于相关任务。
- 自动重试次数、间隔、抖动、预算计数范围及可见文案，在任务模块实施提案中给出具体值；本轮没有确认任何数字。
- 来源收藏分页、授权、资源展开和增量归档能力仍需独立验证；这些行为决策不代表 Pixiv/hanime1 已接通。

## 4. 后续验收场景

以下是未来实施的验收要求，本轮没有执行测试。

1. 同一轮含多个作品，其中一个失败，其余完成；汇总能定位失败作品。
2. 第二轮不重复归档已完成作品；未完成项按剩余重试预算处理。
3. 来源列表移除已归档作品后，既有媒体和元数据仍存在。
4. 多图作品有一张失败，不进入已归档集合；恢复后补齐并只提交一次。
5. 持续失败达到重试预算后，重启应用、下一轮订阅均不会使其无限自动重试；用户可显式重试。
6. 授权失效或空间不足时，暂停依赖该资源的任务，保留检查点及可操作说明。
