## 1. 下一阶段要带来什么

从现在的“启动服务、读取一张样本”进入“应用认识自己的库”。先在 Mac 落地普通库和加密库的配置、保存与校验流程；Flutter 共享模型和界面，Android 接同一契约。Android 有新增功能时再合并交付单 arm64 优化包，不单独发旧功能瘦身包要求重测。

W02 的本地验收使用新建的项目测试目录、公开合成素材及临时测试秘密。主人的既有 OpenList、百度账户和 Crypt 库均不作为测试输入。

## 2. 分两批实现

| 批次 | 实施内容 | 应当看到的结果 |
|---|---|---|
| W02-A：Mac 优先、共享模型 | 库/完整 profile/本机映射模型，配置表单与列表，版本化私有配置；本机秘密接口及 Mac 钥匙串；应用私有 Local 测试挂载和受限库访问；合成 Crypt 读回证明 | 可保存普通/加密测试库；重开仍能取得自己的配置和测试秘密；参数错误或无证据时显示待核实，不能显示为空库成功 |
| W02-B：Android 接入 | Android Keystore 保护秘密、私有密文文件、同一库契约及受限核心桥接；系统输入句柄适配；新功能的优化 APK 构建检查 | Android 具备同样的新功能入口；只交付一个 arm64 包，由 Owner 自行安装时集中验收新增功能 |

Mac 是开发与先行验收平台，不是手机的媒体服务器。每台设备仍通过自己的核心读取自己的映射。Windows 保留接口和明确的不支持提示，实机继续暂缓。

## 3. 数据与校验规则

- `VaultConfig` 保存稳定库 ID、普通/加密模式、提供者引用、选定根定位、profile 引用及配置版本。`LocalMount` 单独保存安装实例、核心前缀和本机状态；禁止把 Mac 前缀当成手机永久路径。
- `CryptProfile` 必须显式表达密码引用、salt 引用（允许明确为空）、文件名模式、目录名模式、名称编码、后缀和 profile 版本。导入既有配置时不替用户填默认值、不改模式、不换钥；缺失项阻止验证。上游 OpenList `drivers/crypt/meta.go`、`driver.go` 与 rclone 格式仍是兼容基线。
- 普通配置只写秘密引用。密码、salt、核心管理员能力、系统文件句柄内容不进入普通配置、状态快照或日志。输入表单中的秘密仅短时使用，关闭或提交后清空，不宣称运行时不存在明文。
- 分开记录“结构合法”“核心接受”“已用已知内容证明匹配”。空列表、核心启动成功和成功创建 Crypt 驱动都不能证明既有 profile 正确。没有已知内容证明时状态为 `PROFILE_UNVERIFIED`。
- 使用独立准备并登记长度/SHA-256 的合成文件和完整 profile；通过固定 Crypt 兼容实现生成/读取测试材料。只做同一实现的往返不能单独宣称所有既有库互通。错误密码、salt、名称/目录模式及编码分别检查；无法判定的情况保留待核实。
- 库内位置只接受相对路径，拒绝 `..`、绝对路径和编码绕行；核心管理端仅能修改本应用登记的测试挂载，不能透传任意管理请求。新建、验证、保存失败不发布可用状态；遗留的自有挂载/秘密引用必须可对账。
- 修改库配置或移除本机映射不删除媒体。已写入数据的 profile 不允许原位更换加密参数，变更需走后续独立迁移流程。

## 4. 秘密及文件访问

优先使用现有平台能力，不新增密码学算法，也不为本批安装通用安全存储插件：

| 平台 | 计划实现 | 边界 |
|---|---|---|
| macOS | 通过 Security 框架保存本应用命名空间下的测试秘密；系统文件选择与受控 security-scoped bookmark/读取句柄 | 只读写自己的条目；不枚举其他钥匙串项，不自动批准系统弹窗；无法取得访问权时明确失败 |
| Android | 密钥由 Android Keystore 管理，以系统 AES-GCM 保护私有文件中的测试秘密；输入采用系统 `content://` 句柄与授权状态 | 不把 URI 猜成文件路径；本批核心 Local 库仍落应用私有测试目录，不直接把任意 SAF 目录冒充可挂载的 POSIX 目录 |

文件输入适配为后续 W03 提供可读句柄及可选大小。没有持久读取权时返回“需重新选择”；需要复制到工作区的策略与配额留到 W03，不提前无界复制目录。

系统安全存储保护应用自己的秘密，不能消除 stock OpenList 配置中可恢复的副本；运行核心仍依赖私有目录及系统设备保护。保持已确认的路线 A，不假定本机已开启 FileVault、不更改设备安全设置。测试结束仅清理本批明确创建的条目和目录，保留供继续开发的配置时登记其所有权。

| 位置 | 预计工作 |

| `native/openlist_bridge/`、`tools/` | 必要的自有挂载与兼容检查；只改登记的包装，继续固定上游与模块锁 |

首先复用现有 Flutter/Dart、Go、系统框架与缓存，不引入 SQLCipher、账号服务、Python、播放器或数据库服务。若必要依赖缺失，先列出实际构件；任何下载仍计入现有累计台账，不重置余量。不改变共享 SDK 或全局默认。

研发计划包括仅本应用测试命名空间的秘密读写、项目测试素材和实际 Mac 新功能验收；不包括手机 adb/USB、真实账号/云端、个人文件导入、Git stage/commit/push 或发布。

## 6. 本批接受条件

1. 普通库不要求 Crypt 秘密；加密库缺少完整参数时不能保存成“已验证”。
2. 配置重开可恢复，秘密没有出现在配置/日志/错误/状态快照中；秘密丢失或访问被拒时有确定提示，不偷偷生成替代密钥。
3. 自有普通库和合成 Crypt 库可经本机核心完整读回并核对内容；错误 profile、空目录、未知版本和路径逃逸不会被报告为可用空库。
4. 主动失败或中断不留下假成功配置；只对账或清理本应用自有测试挂载、秘密和目录。
5. 只对变更影响运行必要检查。W01-A 三项 Owner 成功反馈保留；Android 新功能包单独标明编译/静态检查与手机实际反馈，不能用前者替代后者。
