## 1. 当前范围与执行顺序

原 Android 草案将手机上传列为 C2、音视频列为 C3。本轮优先使用已经在云端的媒体完成 C3 的可见播放检查，减少先行转移素材的步骤；这是验证顺序调整，不改变三端均应支持本地加密上传的产品要求。C2 手机上传在此之后另定具体路径、样本与校验范围。

主要检查加密入口中的一份音频和一份视频。普通副本只在加密播放失败且无鉴权/配额错误时作一次同样本对照，不强制把成功场景重复四遍。

## 2. 手机操作

### 2.1 音频

1. 在现有测试加密入口打开 `媒体/样本.wav`，先使用页面内置播放器。
2. 播放至结束，观察时间是否从 0 推进到约 10 秒，是否出现错误或一直等待。
3. 这是静音样本，听不到声音是预期现象；只检查读取、解码及播放进度，不验收音质或扬声器输出。

### 2.2 视频与可见拖动

1. 打开同目录 `样本.mp4`，先使用内置播放器。观察是否显示约 45 秒总长、彩色测试画面及画面里的计时文字。
2. 播放约 2—3 秒，确认画面与进度继续变化。
3. 拖到约 22 秒，再播放约 2—3 秒。观察实际画面时间码是否接近该位置并继续变化，不能只看进度条移动。
4. 再拖到约 40 秒，确认实际画面和计时继续推进，然后停止本轮播放。无需反复往返拖动或把整片重复播放。

每个媒体只作一轮初次打开，视频只作上述两次定位。若自动跳到其他播放器，记录实际播放器名称及跳转过程，不新增安装。出现错误或约 30 秒仍持续等待，停止该场景并反馈，不循环刷新重试。

若只有加密播放失败，且没有登录、权限、配额或异常授权提示，可对同类型普通副本作一次相同步骤，以区分编码/播放器与加密链路。普通副本成功不替代加密场景通过；遇鉴权/配额错误则停止后续请求。

## 3. 本轮接受条件与反馈

| 项目 | 可见通过条件 | 当前结果 |
|---|---|---|
| 加密音频 | 内置或明确记录的播放器计时推进至约 10 秒，无播放错误 | 用户反馈正常 |
| 加密视频开始播放 | 正确时长、实际画面及计时推进 | 用户反馈正常 |
| 中段定位 | 实际画面定位到约 22 秒，并能继续播放 | 用户反馈正常 |
| 尾段定位 | 实际画面定位到约 40 秒，并能继续播放 | 用户反馈正常 |
| 播放器路径 | 按内置播放器指引操作，外部跳转另报 | 未报告外部跳转；实际名称未单独提供 |

可直接反馈：`音频：正常/异常；视频：正常/异常；22秒：正常/异常；40秒：正常/异常；播放器：内置/名称`。如果某次定位明显等待，可补充大概几秒及错误现象，不要求精确测速或含秘密的日志/链接。

结果来自用户对上述四项的合并反馈“全部正常”；助手没有连接或控制手机，也没有截图或手机响应体。可见播放及定位场景按用户报告通过，未补写精确时间、上游流量、严格缓存或全文件摘要证据。

## 4. 资源与证据边界

- 优先 Wi-Fi。视频对象约 42.8MiB（约 44.9MB），音频约 0.92MiB；播放器预取、范围读取、TLS 与元信息可能增加流量，对象大小不是总流量硬上限。
- 本轮没有手机端的转发器字节计数或精确网络配额，不把 Mac 的 512MiB 预算或先前范围数据冒充手机观测。
- 拖动成功只说明本轮可见定位与继续播放可用；没有 HTTP 206/416、Content-Range、冷缓存、上游读取字节或精确定位延迟观测时，不声称手机高效 Range 已严格通过。
- 静音短样本不证明 ASMR 音质、后台/锁屏、蓝牙、长音频、大视频、字幕、多音轨、其他编码或离线播放能力。
- 云端对象与现有手机配置默认保留。没有新授权、复制百度凭证、恢复备份、权限变更、手机远程控制或 Mac 服务启动。
