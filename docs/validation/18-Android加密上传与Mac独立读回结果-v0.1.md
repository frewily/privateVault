## 4. 资源、记录与退出

本轮使用单独的 C2 转发器记录及 32MiB 累计 TLS 隧道上限，不混入 B2。C2 上行 18,546 字节、下行 46,993 字节，合计 **65,539 字节**；未触发预算或范围上限。它包含该验证实例的 TLS/元信息开销，不包含 DNS、环回和 TCP/IP 头，也不代表手机上传流量。

单次完整 PNG 读回观测耗时 3.5921 秒，只是这一小样本的一次观测，不作吞吐或视频拖动性能结论。响应体保护上限 32KiB，本轮实际为 9,763 字节。

工作区逻辑大小由 289,069,041 字节到 289,086,812 字节，低于 2GiB 操作预算；末次系统可用 250,209,615,872 字节，高于 15GiB 保留下限。这些是离散快照，不是连续精确峰值或内核磁盘配额。

临时核心/转发器退出码分别为 0/0，端口 15245/15246 在程序收尾及独立复核时均未见监听。临时 TempDir/日志路径的配置改动已按原文件恢复；没有恢复旧数据库或覆盖新凭证状态。测试提供者的最新状态另存于私有区，刷新值相较接收种子未变；不因此声称刷新轮换或到期行为已验证。

B2 累计记录逐字节保持不变，且再次与已归档 B2 证据中的计数核对一致。没有常驻、开机启动、原环境修改、Git 提交或推送。

## 5. 当前可行性结论与剩余范围

当前样本已补齐两个方向的证据：Mac 加密上传的媒体可由手机解密浏览/播放（用户报告）；手机经 Crypt 上传的 PNG 可由 Mac 独立解密并按大小/摘要完整校验（本轮运行证据）。这支持保留“各设备本地 OpenList/Crypt＋共享百度存储”的底层方向，不需要把 Mac 作为手机解密服务器。

结论仍限于这些样本和已记录配置。不同 OpenList 版本的这条 PNG 链路通过，不等于独立 rclone 客户端、Windows、6TB 全库、大视频暂存、后台/锁屏、离线或来源站下载已经通过。普通越界 Range 的 400/416 差异及上游错误链接脱敏要求仍按 B2 报告保留。

PrivateVault 的统一账号、元信息自动同步、可靠任务和完整三端 UI 仍未实现。下一步可据这些结果收敛后续设计与最小开发边界，后台/离线、来源适配及 Windows 分别保留验收项，不因本轮成功自动进入业务开发。

后续用户决定当前平台验证先收尾、Windows 等设备可用时再测，不阻塞继续设计。剩余验收项保留为风险而非当前新增测试指令，见[推进边界 19](../research/19-平台验证收尾与后续设计边界-v0.1.md)；本报告中的 Windows 未实测及其他证据边界不变。
