## 2. 手机操作

1. 从普通“百度网盘”入口到上述 `plain/媒体/样本.png`，通过文件操作菜单的“下载”取得原文件。保留原始 PNG 字节，不使用截图或经过编辑、压缩、转换的图片。下载后能在手机文件/下载管理中找到这一份文件。
2. 回到首页，进入 **`PrivateVault-C1-Crypt`** 测试入口，在其根目录新建 `Android-C2-20261028-01` 文件夹。确认是这个测试入口，而不是原有真实 Crypt 库或普通百度目录。
3. 进入新文件夹，选择“上传”，通过系统文件选择器选中刚下载的 PNG，应用级上传一次；不选择其他本地文件。
4. 等待任务结束并刷新该新文件夹，观察文件是否出现，打开上传后的图片确认可显示。图片显示可先记“上传后可预览”，完整性仍待后续读回。
5. 告诉助手“已上传”，并报告成功/报错、实际文件名，以及图片能否显示。首次遇权限、配额、网络、目录冲突或上传失败即先反馈，不自动反复上传。

如文件选择器只授予所选样本访问即可继续；若应用要求扩大到所有文件权限，先报告提示，不自动放宽权限或安装其他软件。Mac 正常使用即可，它不负责手机上传过程中的加密或转发。

## 3. 云端写入与保留边界

| 操作 | 范围 |
|---|---|
| 下载源样本 | 1 份既有普通 PNG 原文件，使用现有授权 |
| 新建目录 | Crypt 库根下 1 个新测试子目录，底层由手机加密目录名 |
| 上传 | 1 张 PNG，1 次应用级尝试；驱动内部请求/重试不等同于该计数 |
| 预期新增媒体对象 | 1 个密文对象；如输入确为源 PNG，按既有格式预计约 9,811 字节，实际待核对 |
| 默认保留 | 新目录、上传文件和本机验证材料均保留 |
| 范围外 | 不覆盖/删除原文件，不追加音视频、不重新授权、不增加百度驱动或修改原挂载 |

9,763/9,811 字节不是总网络流量。元信息、初始化、上传会话和内部尝试会增加传输；本轮不做并发、压力、故障注入或大文件暂存测试。

## 4. 上传后独立读回方案

收到用户明确的上传结果后，先确认该新子目录中的实际文件名，再使用 Mac 原隔离验证实例作为**另一个验证客户端**独立解密读回。此角色只为验证手机上传结果，与为手机提供媒体服务不同。

只读范围限定为新目录及其中唯一 PNG：

1. 沿用原测试实例、既有 Crypt profile 及最新测试凭证状态；不导入旧种子，不读取原 Desktop 配置，不复制手机百度凭证或新建第二个百度驱动。
2. 如需启动临时核心/转发器，执行前落实本轮记录与边界；B2 的既有累计记录保持冻结，不能将新流量混入原 B2 结论。初始化仍可能请求账户信息或自动刷新，不能称绝无授权状态变化。
3. 仅读取已确定新测试目录，确认仅有预期上传对象；完整解密读回一次，校验 **9,763 字节与上述 SHA-256**。不同文件名本身不改变内容摘要。
4. 在该已知新目录范围内核对密文名称/大小，不浏览用户原库或全盘。独立记录筛选结果，停止本轮临时服务。

此处是下一步验证范围，不是已经启动 Mac 或完成网络请求的事实。若实际无法安全复用原实例/记录，应先说明替代方案，不通过扩大访问原配置来补足。
