## 2. Flutter 为什么保留两个版本

先试用了电脑已有的 3.47.8/Dart 3.13.7：离线依赖恢复、分析和 13 项测试通过，但实际 Mac 构建发现它缺完整 Mac SDK 缓存，尝试取得框架时被禁用的网络入口拦住。没有下载框架，没有伪造缓存完整标记。

因此没有把本项目升级到 3.47.8，而是将已经验证的 **3.47.5/Dart 3.13.4** 从项目移入共享版本目录。共享化后重新通过分析、13 项测试和实际 Mac 集成；普通 App 入口也已重新构建。

两份 SDK 属于不同版本，目前都保留。旧项目 SDK 约 1.95GiB 的移动**不计作释放磁盘空间**。以后相同版本的其他项目直接复用相应目录；若要统一到 3.47.8，仍需补齐该版本的构件并回归，不能在已耗尽的下载授权下自行处理。

## 3. 终端入口和现有设置

`~/.local/bin/` 已有本次新增的 `go`、`gofmt`、`gradle`、`gomobile`、`gobind` 入口；新终端可直接使用。默认 Go/Gradle 通过 `Library/Developer/.../current` 选择，项目则直接指定版本目录，避免全局默认变化带动项目静默升级。

`~/.config/development-tools/env.zsh` 由 `.zprofile`、`.zshrc` 的各一个管理段加载。原配置内容保留，修改前备份在：

`~/.config/development-tools/backups/20261101-privatevault/`

备份文件权限 0600，日期目录权限 0700，不进入仓库或普通证据文件。当前已打开的终端可只加载上述 env.zsh，或直接新开终端。

迁移前直接启动 Gradle 时选中了 Java 8；本轮没有改变原全局 JAVA_HOME。全局 `gradle` 命令包装单独选择已有 JDK 17，项目的 Gradle/Android 入口同样选择 JDK 17。其他项目的 Wrapper 仍遵循各自的版本与 JDK 设置。

Gradle Wrapper 已从本地校验通过的官方 ZIP 完成标准缓存安装并离线运行。对照 314 个发行文件逐一确认与旧实体相同后，工具目录改为指向标准 Wrapper 实体，移除临时重复解包。后续采用相同版本、相同 bin 分发 URL 的 Wrapper 可直接复用；其他版本或 all 分发包不能据此宣称无需下载。

## 5. 占用和清理

公开 Pub 包和缓存先核对冲突再迁移，已有版本内容不一致时会保留并停止，不覆盖电脑已有包。Go 校验检查点也迁入标准 GOPATH。

回归通过后，核对没有进程使用本次旧目录，清理旧 Pub 重复项和原 Gradle 生成缓存，合计 **325.95MiB（du 分配块口径）**。此数字是移除目录的占用，不是整机净空闲变化；新生成的共享缓存、移动的 SDK/模块缓存均不计入“节省”。临时重复解包的 Gradle 也已移除，但不把它计作原有缓存清理收益。

共享 SDK、共享缓存、原有 3.47.8、已有全局 Gradle 配置与其他项目均保留。清理 PrivateVault 时不能沿 `.tools/` 的兼容链接删除共享实体。
