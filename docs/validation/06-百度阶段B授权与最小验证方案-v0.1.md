## 1. 推荐顺序

1. **B0：确认接入方式和授权范围。** 只收集非秘密配置特征，不复制原挂载、令牌、数据库或应用参数。
2. **B1：最小云端门槛。** 在全新、明确允许的测试目录中，仅对一张自制 PNG 做普通与加密各一次上传、完整读回和摘要核对；配额不足则分窗口执行。
3. **B2：音视频、空间与真实 Range。** B1 通过并审阅结果后，再批准 WAV/MP4、云端入站字节观测与播放范围。
4. **B3：恢复、到期与三端。** 云端中断、令牌轮换、新设备、Windows/Android、Mac 睡眠分别立项；不顺带影响现有挂载。

这样先用约 19KiB 的云端媒体对象验证接入、目录和 Crypt 基础，再扩大到视频。B1 成功不等于 B2/B3 或完整产品通过。

## 3. 非秘密信息在哪里核对

指的是 **OpenList 的网页管理页面 → 存储 → 对应百度网盘挂载 → 编辑配置**，不是百度网盘客户端设置，也未必是 Desktop 应用的通用设置页。2026-10-27 用户已提供对应存储列表和两个配置字段的截图；现有界面将下载方式标为“下载接口”。不假设其他版本的按钮名称完全一致。

若现有界面已经打开，只需由用户核对并用文字报告：

| 要核对的内容 | 可报告的值 | 不需要提供 |
|---|---|---|
| 使用在线 API / use online API | 已确认开启，无需重复核对 | API 完整地址、查询参数 |
| 下载接口 / Download API | 已确认“官方”，对应本方案的 official 方式 | 实际下载链接、Cookie、请求头 |
| 在线刷新 API 地址 | 已确认主机为 `api.oplist.org`，路径与公开默认端点相符，无需重复提供 | 带查询参数的 URL、实际刷新请求或任何凭证 |
| 是否自己创建过百度开放平台应用 | 是、否、不确定 | App ID、Client Secret、账户资料 |

不要复制整页、导出配置、截图含秘密的编辑页、点击获取令牌/刷新/保存、取消旧授权，或修改原挂载。若只看到云盘文件列表，说明尚未到存储配置；找不到就保留未知，不按默认值猜测。

## 4. 凭证与服务边界：新核对结果

### 4.1 在线刷新服务是额外的凭证接收方

固定版本 `meta.go` 定义 `use_online_api`、`api_url_address`、`client_id`、`client_secret`、`refresh_token`；源码默认在线服务地址为 `https://api.oplist.org/baiduyun/renewapi`。2026-10-27 用户提供的地址与之相符，S1 与 S4 已重新读取核对。[S1][S4]

S4 将其描述为 OpenList 提供的中转刷新方式；下载选项“官方”描述的是百度下载接口，不表示凭证刷新直接发送给百度。两条链路分别记录，不能混为一个“全程百度第一方直连”的结论。

启用在线方式且地址非空时，刷新函数将刷新令牌发到配置地址；关闭后走百度 OAuth 端点，并要求 Client ID/Secret。[S2]

实际执行前应确认运营方、用途和用户是否信任相应服务。源码用查询参数传递相关凭证，不能保存原始 URL、浏览器历史导出、完整请求日志或未经筛选的错误正文。

本方案不默认批准向第三方刷新服务发送凭证，也不采用工具文档中借用其他应用秘密的路径。

### 4.2 初始化和“只读”也会触发外部行为

百度驱动 `Init` 会请求账户基本/会员信息；请求遇到特定凭证错误时，会尝试刷新并保存新令牌。请求包装具有最多三次尝试的逻辑。[S2][S3]

因此，把原刷新令牌复制到测试实例后“只列目录”，也不能认为不会改变授权状态。**填好凭证并启用挂载属于实际百度访问步骤**，不是纯离线准备。

### 4.3 一个测试授权只配一个百度驱动

推荐结构：一个百度驱动挂载新测试根目录；其普通子目录直接使用，密文子目录上再建立一个 Crypt 视图。

不为“普通”和“加密”分别创建两个复制同一刷新令牌的百度驱动。不同挂载保存各自的配置副本，会增加刷新所有权和旧值覆盖问题；一个核心进程不自动消除这些问题。

这只是本轮测试的单一凭证所有者安排，不是最终 PrivateVault 可信账号服务与多端刷新协议已经实现。

### 4.4 本次收敛结果

现有路径已识别为“OpenList 文档介绍的在线刷新配置＋百度官方下载方式”，无需继续查找原配置或凭证。当前只确认配置与公开资料对应，没有请求刷新端点、测试服务在线状态或证明其当前运行实现。

为判断能否新建不影响旧挂载的测试授权，本轮还做了有限公开检索：OpenListTeam 组织内检索 `oplist token api` 仓库，以及在 OpenList 问题单中检索百度多设备刷新、重新授权失效相关关键词，未获得匹配结果。这不是不存在相关实现/说明的证明，也不是授权互不影响的证据。

R2 的接入类型已明确，用户也已选择优先采用 R2。后续在官方 OpenList-APIPages 仓库找到并追踪了百度授权/刷新函数，证据与新进展以研究 07 为准；“新授权不影响旧挂载”仍未闭合，不能把源码存在当作百度签发行为的保证。下一步提出一次受控新授权，需明确可能影响旧登录的边界；R1 仅作有明确障碍时重新评估的候选，不自动切换。

## 5. 授权路线比较与决策条件

| 路线 | 优点 | 前提/代价 | 本轮建议 |
|---|---|---|---|
| R1：专用自有百度应用＋直接官方授权/刷新 | 应用身份和凭证流向较清楚；可把测试与原挂载的应用身份分开 | 需用户具备创建/使用资格，确认目录、接口及配额；用户私下完成申请与授权 | 保留候选，当前不推进 |
| R2：明确可信的 OpenList 授权/刷新服务＋专用测试授权 | 可使用服务端预设应用参数，减少自行申请应用的步骤 | 必须明确服务接收什么、允许何种接入，并处理新授权对原授权影响尚不确定的情况 | 用户已选择，作为当前推进路线；实际账号操作另有范围 |
| R3：直接借用原挂载或复制配置 | 表面配置少 | 原凭证、原根目录和测试环境耦合；现有软件完整性及授权影响未明确 | 当前不采用 |

R1 中，新应用的默认应用目录可能足够做小样本验证，但不证明最终可以接入用户原有任意收藏目录。目录级新授权和现有驱动仍需核对，不能把新格式令牌直接填入旧接口后再碰运气。

R2 中，重新授权是否形成独立刷新链、是否影响同一应用的旧挂载，目前未确认。不能把“再登录一次”写成无影响承诺；可在用户明确接受旧挂载可能需重新登录后进行一次受控新授权，或继续保持准备状态，不自动换成 A。

用户已完成第 3 节两项选项及刷新服务地址核对，并选定 R2，B0.1 的一次授权和接收已有用户反馈及本机标记。下一步按提案 09 确认空目录就绪与两份 PNG 测试范围；不得复制旧刷新令牌，不把本机保存成功当作百度 API 验证通过。

## 6. B1 的具体候选范围

### 6.1 本机环境

- 复用阶段 A 已核对的官方核心文件，执行前确认仍为原摘要/签名版本；不下载另一版本，不安装新依赖。
- 新建独立 `privatevault-baidu-validation-<日期>-<唯一标识>` 临时目录，使用新的配置、数据库、日志、Crypt 测试参数和恢复材料；不复用阶段 A 管理令牌，不混入旧测试挂载。
- 候选只监听 `127.0.0.1:15245`，执行前查冲突；只运行批准期间，不注册开机启动。
- 使用最少本机管理权限和受保护的初始化流程；云端样本不沿用阶段 A 无签名访客预览配置。
- 本机秘密由用户私下输入或受保护的临时流程内部管理，不进入聊天、模型输出和项目文档。不复用真实加密收藏库密钥。

阶段 A 的进程策略封锁外联，不能直接拿来宣布云测可运行。执行前须明确百度授权/API、动态上传主机和下载 CDN 的允许网络范围，并预检本机隔离及观测方法；不静默删除原限制或宣称已做到尚未验证的域名隔离。

### 6.2 云端目录和挂载

用户已选定 `/PrivateVault-验证-20261027/`，当前尚未确认其已创建并为空。按提案 09，由用户先在百度网盘准备该空目录，测试实例直接挂载它，不为创建根目录而扩大到上层列表。该路径仍须处于测试应用真实获准范围；选择路径不证明授权覆盖它，错误时停止，不自动改路径。

逻辑结构：

```text
用户批准且应用获准的测试根目录
├── plain/
│   └── 媒体/样本.png
└── cipher/
    └── 加密目录名/加密文件名
```

一个 `BaiduNetdisk` 挂载仅指向该根，Crypt 视图只指向其中的 `cipher/`。启用挂载即可能发生账户信息请求；除此之外，只列举和操作批准测试根的子树，不递归全盘、接入原收藏目录或修改原挂载。

根目录如已存在且非空，停止；不得清空后复用。子目录创建也属于云端写入，应计入批准范围及配额。

### 6.3 样本、操作与保留

| 项目 | B1 候选上限 |
|---|---|
| 输入 | 阶段 A 自制 PNG 一张，明文 9,763 字节；执行前核对摘要 |
| 正式测试媒体对象 | 普通 PNG 1 个，Crypt 密文 PNG 1 个 |
| 预计媒体对象总大小 | 9,763＋9,811＝19,574 字节；基于已验证格式估算，实际再记录 |
| 目录 | 新测试根及 plain/cipher、媒体目录，预计合计不超过 5 个目录 |
| 应用级上传 | 两个对象各一次；不自动整文件重传 |
| 完整读回 | 普通和解密视图各一次，分别核对长度和 SHA-256 |
| 密文观察 | 只在测试 cipher 子树查看对象名称及必要格式头，不读取真实资料 |
| 并行 | 单任务，上传线程候选值 1 |
| 本机空间 | 工作区 2GiB 操作预算；系统至少保留 15GiB，执行中观测 |
| 保留 | 默认保留全部测试云端对象和受保护恢复材料；不发起删除 |

19,574 字节是成功对象的预计大小，**不是总网络流量硬上限**。握手、元信息请求、重定向、读取、底层自动重试均会增加流量；控制器不再额外循环重试，不代表驱动内部无重试。

B1 不上传 WAV/MP4，不做源站下载、不进行故障注入、凭证到期测试或自动备份，也不创建正式媒体库/元信息同步记录。

### 6.4 配额是执行门槛

先确认可公开取得的应用用途、接口范围及限额，不以 SVIP 替代应用资格或配额。R2 服务的后台审核/配额信息可能无法由用户查看，应记录未知；这种情况下可另行审阅低频、小样本、遇限制即停的探测范围，不要求用户提供服务端应用秘密或后台访问权。

一次 UI 上传可能包含快速上传尝试、哈希准备、预上传、分片及最终创建；列举、下载链接、初始化及刷新又是其他请求。不能以“只有两张图”推断只用两次 API。

若配额说明适用每小时 10 次等低限额，应根据真实接口计费口径拆开普通与加密步骤，允许跨窗口继续。无法明确请求数量/额度归属时，不声称具有精确请求硬上限；在新的探测范围获准前停留在授权准备，不能凭猜测启动整组验证。

任何权限、限额、异常授权、非预期目标或完整性错误，停止后续调度并记录脱敏结果。内部可能已发出的重试需要单独记录，不能承诺从未产生。

## 7. B1 验收与失败判定

| 检查 | 通过条件 | 未通过后的动作 |
|---|---|---|
| 应用/接收方 | 身份、目录权限、刷新接收方及新授权影响明确 | 不输入或启用凭证 |
| 目录边界 | 新根不存在冲突，挂载根与获准根一致 | 不扫描上级或自动改路径 |
| 普通上传 | 目标长度、完整读回摘要与 PNG 相符 | 标记未验证，不继续加密步骤 |
| Crypt 上传 | 明文视图读回摘要相符，cipher 子树名称/格式符合本轮 profile | 保留失败证据，不标记加密库可用 |
| 暂存/日志 | 临时文件位于批准工作区，普通报告不含秘密 | 停止扩大测试，先定位边界 |
| 结束 | 仅停止本次核心；记录云端保留清单及本机占用 | 不删除未知对象、不影响旧应用 |

不能以 HTTP 200、目录里有文件、进度 100% 或缩略图可见替代完整性验收。阶段 A 的半成品发现仍成立；本轮 B1 也不证明可靠归档任务已经实现。

## 8. B2 扩展提案（历史草案；已另行批准并归档）

2026-10-28 更新：具体批准范围见[提案 12](12-B2音视频与云端Range验证范围-v0.1.md)，结果见[报告 13](13-B2音视频播放与Range验证结果-v0.1.md)。以下为当时扩展草案，不能将“未获本轮批准”理解为 B2 从未获准或从未执行。

B1 通过后，再考虑复用自制 WAV 与 MP4，普通/Crypt 各上传一次。连同 B1 共 6 个媒体对象，按阶段 A 尺寸估算约 91,655,464 字节（87.4MiB）；这是对象体量，不包含重试和网络开销，也未获本轮实际云端执行批准。

扩展验收包括：

- 完整普通/解密读回与摘要；实际原件、密文暂存及读取缓存占用，注明采样间隔，不能把观测最大值叫精确峰值。
- 下载方式限定 `official`，由本机服务按第一方要求访问百度，不采用 crack/crack_video 分支。[S3][S4]
- 云端首、中、尾、跨块、后缀、开放结束及非法范围；比较明文字节、206/416 和 Content-Range。
- 将完整读回、Range 与浏览器播放安排为独立观测，冷缓存用新进程/确认未下载前缀的试次，不只清浏览器缓存。
- 只统计本次核心云端连接的入站字节，排除环回连接；不抓取数据包内容、URL 查询参数或账户流量。观测工具和权限须先核对。
- 每个 Range 试次请求少量目标字节并观测传输体量；若读尾部需要下载接近整个文件，标记高效随机读取未通过。
- 若只能观察下游响应，无法可靠归属上游字节，则只能给出“范围正确性通过，云端效率未知”。不通过增装证书、解密 TLS 或抓取其他应用流量补证据。

视频样本约 42.8MiB，只能作为基础流量放大与播放验证，不能外推大视频、弱网或全库体验。移动端锁屏和后台行为另测。
