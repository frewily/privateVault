## 2. 备份导入能解决什么

用户已有实践支持把导出/导入作为早期的配置迁移方式，无需从零重新填写每条存储。不同设备接入同一个云端目录之后，云端文件由各设备重新读取，通常不需要每增加一个文件就重新导入配置。

| 变化 | 应如何理解 |
|---|---|
| 电脑新增一条 Crypt 存储/挂载 | 新增的是设备配置；手机需要获得这条配置。用户当前手动更新备份的理解成立 |
| 已有 Crypt 库内新增文件或子文件夹 | 改变的是云端内容；匹配配置的设备通常刷新列表即可看见，缓存/权限异常另查，不默认重新导入整份备份 |
| 修改库根路径、Crypt 参数或设备设置 | 属于配置变更，需要有明确的更新流程；不能用旧备份随意覆盖当前状态 |
| 百度访问/刷新凭证更新 | 固定版本驱动会把刷新结果保存到本机；多端版本协调及失效规则仍需验证 |
| PrivateVault 作者、标签、封面、播放进度等变化 | 本轮没有相应同步实现；OpenList 配置迁移成功不替代该模块验收 |

因此记录为：**用户已通过手动备份实现多端配置迁移，并能访问既有云端资料；尚未验证持续自动配置同步。** 未读取实际备份类型、字段或导入覆盖语义，也未确认备份是否包含全部秘密；不要求用户把它发进聊天。

原来的备份导入是用户已自行完成的操作，本次不撤销、不要求重做或重新授权。若备份包含百度刷新凭证，多设备可能持有副本；当前没有发生冲突的证据，也没有独立刷新链或长期无冲突的证明。后续不得为了试验此问题而轮流刷新、使旧登录失效或反复导入旧快照。

### 4.0 当前操作顺序与记录

1. **目录定位：用户报告完成。** 只核对手机现有挂载能否到达指定测试区，`plain`、`cipher` 均可见。
2. **C1a 普通 PNG：当前场景按用户报告通过。** 用户反馈 `plain/媒体/样本.png` 可查看，并确认 Mac 当时已休眠、该图为手机首次打开。沿用原配置，没有进行测试 Crypt 配置或秘密转移。该结果不扩展为响应体摘要、严格冷缓存或上游流量验收。
3. **C1b 测试 Crypt：解密及 PNG 显示按用户报告通过。** 新增配置已另行获准；密码差异经单项替换后恢复。加密图休眠后首次开图未执行，未补写摘要或冷缓存结果。

执行口径更新：用户澄清当前手机本地核心直连百度、Mac 未充当媒体服务器，因此加密图片阶段不再强制重复 Mac 休眠。下文原提案中的相关步骤保留其历史语境，当前作为可选演示；未执行用例仍如实记录，手机自身切应用、锁屏及系统终止行为继续独立验证。

C1a 应反馈 Mac 是否确实休眠、图片是否完整显示、是否曾在手机打开/下载过及是否出现错误。只显示目录、缩略图或缓存命中不能升级为新的云端独立读取证据；用户反馈也不能替代响应体摘要、请求量或缓存状态测量。因助手运行在 Mac 上，整机休眠由用户完成，恢复后汇报，不由助手操作后推断结果。

### 4.1 具体操作范围

1. 由用户在手机现有应用里核对本机服务运行状态/核心版本；只报告非秘密信息，不发完整日志或配置。此次需要启动现有服务及后续云端读取，须在本提案获准后进行。
2. 沿用手机已有百度挂载，在其授权范围内定位 `/PrivateVault-验证-20261027/`。如果该目录不在挂载范围，不修改原根目录或扩大授权，停止并重新设计映射。
3. 如需访问 B1/B2 密文，**只新增一条测试 Crypt 视图**，引用手机已有百度挂载下的测试 `cipher/`。不再新建一个复制同凭证的百度驱动，也不把 Mac B1/B2 的百度测试授权复制到手机。
4. 测试 Crypt 视图需要 B1 的测试密码/salt、名称模式、编码和路径映射。实际开始前另给用户可核对的字段清单与私下转移方式；秘密只给用户自己的手机 OpenList，不进聊天、截图、项目或普通日志。不得使用用户正式库密钥替代，也不得通过导入整份测试数据库覆盖手机原配置。
5. 手机分别打开普通测试 PNG 和通过测试 Crypt 还原的 PNG，各一份，记录图片是否真实显示及本机读取路径；不预读 WAV/MP4、不自动批量预览。
6. 内容完整性与可见性分级：图片显示只能记预览通过。若手机没有现成摘要核对能力，不新增工具；下载字节/摘要验证留待单独约定的安全方式，不能据缩略图宣布完整性通过。
7. Mac 临时测试核心和转发器保持关闭。为了确认不依赖其他 Mac 服务，应在实际范围获准后由用户短暂让 Mac 休眠，再在手机本机刷新/重新读取指定样本；执行助手所在 Mac 会暂停，因此该步骤由用户完成并反馈，不能由助手发出整机休眠命令后继续声称观察成功。
