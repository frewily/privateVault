## 2. 失败点与根因证据

脱敏错误的关键部分为：

```text
failed to resolve host: c5.pcs.baidu.com
lookup c5.pcs.baidu.com: no such host
```

原始响应包含请求 URL，留在受保护临时目录；项目导出的诊断已去除 URL 和凭证。未出现能够归为百度权限/配额的 errno，不能把该错误写成百度拒绝上传。

### 2.1 DNS 对比

停掉两个临时进程后，在不使用任何凭证、不请求百度文件 API 的情况下，只做域名解析：

| 环境 | `c5.pcs.baidu.com` | `pan.baidu.com` | 外部 TCP 直连 |
|---|---|---|---|
| 普通本机环境 | 解析成功 | 解析成功 | 未在该对比中测试 |
| 首轮核心隔离规则 | 解析失败，gaierror 8 | 解析失败，gaierror 8 | 首轮预检已验证被拒绝 |
| DNS 修正候选规则，仅诊断进程 | 解析成功 | 解析成功 | 仍被拒绝，EPERM |

候选只额外允许访问系统本机 Unix socket `/private/var/run/mDNSResponder`，没有放行外部 TCP 直连、关闭 TLS 校验或修改系统 DNS/代理设置。本机系统沙箱配置中也有此类规则示例；这里只读取例子，没有编辑系统文件。

### 2.2 与固定版本源码吻合

[固定版本 `safeTransport.RoundTrip`](https://github.com/OpenListTeam/OpenList/blob/25e4eb663ffb73991a68d85df4f690d48ad137a6/internal/net/serve.go#L368-L381) 在调用基础 HTTP transport 前，会执行 `DefaultResolver.LookupIPAddr`。即使基础 transport 使用 HTTPS 代理，这一步仍先在核心进程中运行。

[百度上传流程](https://github.com/OpenListTeam/OpenList/blob/25e4eb663ffb73991a68d85df4f690d48ad137a6/drivers/baidu_netdisk/driver.go#L278-L351) 会取得上传地址再发分片请求；[动态地址解析](https://github.com/OpenListTeam/OpenList/blob/25e4eb663ffb73991a68d85df4f690d48ad137a6/drivers/baidu_netdisk/util.go#L400-L447) 不代表核心可完全不做本机 DNS。

本轮错误、对比与源码形成一致解释：**临时验证环境的网络限制遗漏了核心需要的本机解析接口。首轮预检检查了代理访问，未覆盖该独立解析路径。** 这是本次验证配置的问题，不能据此否定路线 B 或宣称百度 Crypt 不可用。

DNS 候选规则已在无凭证诊断中通过；尚未用于真实核心或完成真实上传，不能把它写成修正后云测已经通过。
