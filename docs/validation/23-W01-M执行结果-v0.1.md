## 2. 实现结果

- Dart 提供统一 CoreHost 接口、中文状态界面、启动/停止/取消/重试和测试图展示。状态带版本序号，迟到的旧消息不能覆盖新状态；原生异常原文不进入界面。
- Mac Swift 控制器管理固定核心、独立数据目录、文件锁、本机回环监听、认证、访客限制、签名读取与完整测试图比较。平台进程管理集中在 Swift，Dart 通过 MethodChannel/EventChannel 使用同一契约。
- 正常启停、启动取消、端口竞争、核心异常退出与残留实例对账均有实现。未知实例不能仅按 PID/端口接管或结束；失败清理只处理本控制器证明拥有的进程与运行目录。
- 已生成并实际构建 Mac Xcode 工程，加入核心及小型监督程序的签名/打包，保持 App Sandbox 开启。实际窗口已认证、完整读回并显示测试图；App、核心与监督程序的实际签名和整个 bundle 的深度校验均通过。
- 沙盒拒绝列出子进程文件描述符，最终采用基础进程身份与系统 CryptoKit 对上游 HS256 令牌的私有配置签名验证。主应用与监督程序用管道保持会话；主应用退出或被强退时，监督程序停止自己保留的核心进程，并写入无秘密的完成记录。没有放宽沙盒、改系统保护或创建常驻系统服务。
- 已提供运行/检查脚本、公开工具链清单、运行说明和 [Owner 导读](../development/Owner导读与随项目学习路线-v0.1.md)。没有加入账号、Crypt 库、下载器、播放器、SQLCipher 或同步业务。

下载始终使用同一官方来源。Dart 和本机测试运行时下载较慢，采用有界并行 Range 读取，核对官方对象长度/MD5 与 ZIP CRC，并另存 SHA-256；没有改镜像或关闭 TLS 校验。人工解包的缓存布局依据固定 SDK 源码，完成所需构件后才写相应版本标记，不把下载成功算作测试通过。

准备中遇到两项已定位的环境问题：官方 Dart ZIP 顶层另含许可文件，初始严格前缀规则拒绝它；在确认完整性与路径安全后只加入这一文件的允许项。浅检出初期缺本地标签，SDK 被识别为 0.0.0-unknown；获取同一官方标签引用后恢复为 3.47.5，没有更换代码提交。

Flutter 通用工具初始化自动取得部分 iOS USB 辅助工具缓存；助手未安装 iOS 模拟器、未生成 iOS 目标，也未改变产品三平台范围。使用统计按执行参数抑制，没有批量更新 Homebrew 或更改系统安全设置。

## 6. 安全、保留项与限制

没有读取旧应用或旧百度授权工作区中的秘密，只复用已校验的公开核心归档。W01 运行秘密由测试宿主新生成，不写入启动参数、普通输出或项目证据。测试期临时秘密位于受限运行目录，正常结束后随对应目录移除。

命令行测试结束后检查其退出状态；负向用例有意保留的模拟未知标记不含真实密钥，仍在忽略的测试工作区。直接启动旧版的 App 强退用例曾留下测试孤儿核心，助手经路径、摘要、工作目录和端口核对后，仅受控停止这一旧测试实例，并保留失败前记录。最终监督程序版重新做了该用例，核心自动退出、重开恢复均通过，未再用外部工具代替产品恢复。

产品代码显式请求的 HTTP 目标仅为本机回环，测试未配置云端存储；本轮没有严格抓取核心全部出站流量，不能宣称已经证明零外连。若主应用与监督程序同时被强杀等，仍会保留待核对信息，不承诺所有复合故障都能自动恢复。当前开发会话令牌设为 1 小时，长时间会话续期与后台媒体生命周期不属于本次通过范围。构件为本地调试签名，未做公开分发、公证或安装器。
