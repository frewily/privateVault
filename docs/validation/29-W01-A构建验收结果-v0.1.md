## 2. 实际权限与隔离

合并后的 APK 清单仅申请：

- `android.permission.INTERNET`：供应用本机 HTTP 等网络调用使用；该权限本身不等于已接通云端。
- `dev.privatevault.w01.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION`：AndroidX 生成、仅本应用签名可用的接收器保护权限，不是存储/照片等运行时授权。

没有全文件、照片视频、通讯录、定位、无障碍、设备管理、前台服务或电池优化豁免权限。应用自动备份关闭；cloud-backup 和 device-transfer 的相关域均排除，已检查实际打包的资源。

核心服务位于 `:pv_core`，exported=false，并在协议层核对 UID、实例与代次。全局明文访问关闭，唯一明文例外为精确的 `127.0.0.1`，不包含子域。实际清单另有 AndroidX ProfileInstallReceiver（受系统 DUMP 权限保护）和非导出的初始化 Provider，不能据此称清单里只有两个组件。

## 3. 本轮实现与构建修正

1. 安卓就绪探测增加本轮核心实例的 HS256 令牌签名证明。签名密钥仅经 Go/JNI 返回 Kotlin 服务内部，不进入 Dart、HTTP 请求、普通日志或证据。错误密钥、内容篡改、错误算法和异常长度不能通过校验；使用标准 HMAC API，没有更改媒体 Crypt 算法。
2. 修正调试工程中 release 变体“关闭代码压缩但仍启用资源裁剪”的冲突；两个选项明确一致。当前只交付调试包。
3. 直接 Gradle 入口原先未传 Flutter 的已安装 NDK 元数据，导致 Flutter 进入用于促使 NDK 下载的空 CMake 兜底。已按固定 SDK 的实际契约传入已核对的 SDK 根和 NDK28.2.13676358，**未安装 CMake、额外SDK或接受许可证**，也未跳过原生库检查。
4. 三个 Google Maven 构件的 Java TLS 连接失败；改用经过同一计数网关的标准 TLS 客户端，从原官方 URL 获取，并核对官方 SHA-1、另存 SHA-256。只补入 Gradle 内容寻址文件，没有换镜像、关闭TLS校验或修改二进制索引。

实际组合仍为共享 Flutter3.47.5/Dart3.13.4、Go1.27.3、固定 gomobile、NDK28.2.13676358/JDK17.0.15、Gradle9.3.1、AGP9.1.0。已解析和执行的 Kotlin 编译器为 **2.4.0**，不再仅依赖早期2.2.21主机诊断。
