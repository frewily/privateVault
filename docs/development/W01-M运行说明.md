## 2. 从项目根目录执行

以下命令已包含在 W01-M 的执行范围，不连接百度或来源网站。

```sh
# 静态检查、Dart 界面与桥接测试；不需要完整 Xcode 图形构建环境。
zsh tools/check_w01_dart.sh

# 原生层的真实核心检查；需要可用的 Swift 命令行工具。
zsh tools/check_w01_native.sh suite

# 使用与产品相同的监督结构进行原生检查。
PV_W01_SUPERVISED=1 zsh tools/check_w01_native.sh suite

# 上一个命令编译原生检查宿主后，验证该宿主被强退后的恢复。
python3 tools/check_w01_recovery.py

# 监督结构的宿主强退恢复检查（先执行监督结构原生检查）。
PV_W01_SUPERVISOR_PATH="$PWD/.local/w01/core_supervisor" python3 tools/check_w01_recovery.py

# 完整 Xcode 就绪后，构建并运行 Mac 开发版。
zsh tools/run_w01_macos.sh
```

应用会显示启动、停止、重试和测试图结果。点击启动后，会校验固定核心、创建独立运行目录、完成本机认证、禁用访客读取、打开签名读取要求，并通过核心读回 `样本.png`。

这张图是自制测试输入，不会导入个人媒体。没有上传、删除云端文件、登录账号或原 OpenList 管理入口。关闭开发版时，父应用管道结束会通知自有监督程序停止核心；主应用被强退时同样由该监督程序清理自己的子进程。重开先核对完成记录，不仅凭 PID 或端口结束进程。

## 3. 完整 Xcode 就绪后的验收顺序

本轮已按以下顺序完成；修改或升级这些边界时再做相应回归，不必日常无理由重复全部检查。

1. 记录 Xcode 版本和首次启动状态，用固定 SDK 构建开发版；遇到新依赖或系统影响先核对范围。
2. 核对 App ID 为 `dev.privatevault.w01`，App Sandbox 仍开启。独立核心副本作为辅助程序签名，原始公开归档不改动。
3. 验证真实窗口的启动、停止、重试、图片读取，以及签名辅助程序在沙盒内可用。
4. 执行 `integration_test/w01_macos_test.dart` 的实际 Mac 集成检查，再验证窗口正常退出/强退后的进程和恢复行为。
5. 把结果补入阶段报告。不能把现有原生命令行或 Widget 测试的通过直接算作这些项目通过。

SDK 自带的 Mac 集成测试组件已通过 Swift Package Manager 参与构建；没有安装 CocoaPods。当前开发测试目标先设 macOS 12.0 以容纳 SDK 测试组件，未据此确定正式产品最低系统版本。使用构建脚本前先停止、退出现有开发版；脚本会拒绝覆盖仍在运行的自有应用/核心。

## 4. 工作文件与停止

`.tools/` 是项目专用 SDK、包缓存和公开核心。`.local/w01/` 包含编译缓存、下载分段、原生测试工作区与本机检查日志；这些路径已被 Git 忽略。

原生检查结束会停止自身核心并移除对应运行目录；负向用例会有意保留模拟的未知实例标记，以证明没有擅自清理它。测试进程已核对退出。不要把整个临时目录或 Application Support 按年龄批量删除。

实际 App 的运行数据位于它自己的系统沙盒容器，路径由平台接口取得；已实际运行验证。App、OpenList 核心及监督程序的签名校验通过，沙盒保持开启。若主应用和监督程序同时被强制结束，可能仍需保留待核对信息，不承诺任意故障都能自动恢复。工具链与编译缓存可以在明确范围后清理；原 OpenList、旧百度测试恢复材料和共享 SDK 不在本工作包清理范围。
