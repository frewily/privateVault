## 3. 离线检查

在仓库根目录运行，按实际改动选择；已经通过且没有新变化的检查不用反复重跑。

```sh
# 共享 Dart：分析与界面/通道检查
zsh tools/check_w01_dart.sh
# Mac 上运行固定核心，使用新建私有目录和自制图；不是 Android 实机证据
zsh tools/check_w01_android_core.sh
# 主机侧回复门、精确回环端点检查；不是 Kotlin 2.4.0 完整 Android 构建
zsh tools/check_w01_android_contracts.sh
# 实际Android项目的Kotlin2.4.0 JVM契约，仍不执行JNI/设备
zsh tools/check_w01_android_unit.sh
# 只有已登记的源码/模块锁可叠加；现有缓存足够时可重建
zsh tools/build_w01_android_aar.sh
python3 tools/check_w01_android_artifacts.py
# 已有Debug依赖可离线复用；仅在需要诊断时构建，不默认交付大包
zsh tools/build_w01_android_apk.sh debug
python3 tools/check_w01_android_apk.py --mode debug
# 候选优化入口：目前缺lint依赖，会按默认离线策略失败；不要为接手运行
# zsh tools/build_w01_android_apk.sh release
# python3 tools/check_w01_android_apk.py --mode release
```

核心检查会临时监听回环。Mac App 回归另用 `tools/check_w01_macos_regression.sh`，它会构建、运行实际应用测试并恢复普通入口，需要对应运行权限和屏幕条件；不将窗口前置失败当成已人工观察。

## 4. 后续联网构建

当前本轮构建已完成，网关已退出；后续仍按两次明确授权的累计剩余额度和实际所需范围执行，不把本节当成无限下载授权。

1. 先核对最新授权、现有累计记录和缺失构件；合理预估后续流量。不能根据“完全访问”或跨日续接自行扩大 1GiB。
2. 额度明确后，使用计数网关访问固定官方来源。网关仅回环监听，限定公开主机，沿用已有本机代理路由，不改系统代理，也不关闭 TLS/Go 校验。
3. 输入下载使用 `prepare_w01_android.py`，已完成且摘要相符的归档复用；部分下载保留，不无条件从头重复。
4. 复用已有模块与Maven缓存，新功能交付优先构建单 `arm64-v8a` Release；当前先补齐固定lint依赖，不为旧功能单独下载/打包。不要直接运行会预取其他架构/模式的广泛precache；先核对固定Flutter的实际构件需求。
5. 每次APK生成/重建后检查签名指纹、包名、最终合并权限、ABI、ELF及适用的APK ZIP 16KB对齐、大小和摘要，再交付具体安装方案。Debug曾通过静态检查，候选Release还没有实际包的检查结果，不能沿用旧摘要。压缩原生库由Android提取，仍检查其ELF；只有直接映射的未压缩条目要求ZIP数据16KB偏移。

本项目调试包ID为 `dev.privatevault.w01`。当前真实APK清单为INTERNET及本应用签名级动态接收器保护权限，私有目录/回环明文例外与备份排除已检查；AAR/源码清单仍不能替代后续新APK的权限检查。
